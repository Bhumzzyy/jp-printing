## 1. Executive Summary

**JP Printing & Signs** is a modern, high-performance web platform built for a premier commercial printing and architectural signage business based in Ontario, Canada. Managed by Jot Panag and Deepi Panag, the company specializes in commercial printing (business cards, menus, flyers, stationery, calendars) and architectural exterior/interior signage (channel letters, LED displays, acrylic signs, vehicle wraps, window graphics).

### Core Architectural Pillars
- **Zero Runtime Server Overhead (100% SSG)**: Pre-renders **31 static routes** at build time using Next.js App Router's `generateStaticParams`. Every service detail page is pre-compiled into static HTML/CSS/JS.
- **Dual Cloudflare Deployment Strategy**: Fully configured for instant zero-config deployments to **Cloudflare Pages** (via static export in `out/`) and edge serverless deployment to **Cloudflare Workers** via **OpenNext** with persistent incremental caching backed by **Cloudflare R2**.
- **Pure CSS / Zero-Bloat Design System**: Built with Vanilla CSS and scoped CSS Modules (`*.module.css`) styled according to a signature **CMYK** print palette (Cyan `#00b9d6`, Magenta `#e5007d`, Yellow `#f5d800`).
- **Resilient Mobile Responsiveness**: Validated across the entire responsive continuum (**320px, 375px, 390px, 430px, 768px, 1024px, and 1440px+**), guaranteeing 0 horizontal overflow, constrained logo geometry, and fluid `clamp()` typography.

### 3.3 Next.js Application Layer (`src/app/`)

All application routes leverage Next.js App Router conventions with static pre-rendering:

- [`src/app/layout.tsx`](file:///d:/client/jp-printing/src/app/layout.tsx):
  - **Font Optimization**: Imports Google Fonts **Montserrat** (900 weight, `--font-montserrat`) for bold industrial headlines and **Poppins** (800 weight, `--font-poppins`) for punchy UI controls.
  - **Global Shell**: Wraps the DOM with `<RouteScrollReset />` to enforce top-scrolling on route navigation, injects global stylesheets (`globals.css`, `scrollbar.css`, `services.css`), and specifies global OpenGraph and favicon metadata.
- [`src/app/page.tsx`](file:///d:/client/jp-printing/src/app/page.tsx):
  - Composes the high-converting homepage via 9 modular sections (`HomeHero`, `FeaturedProducts`, `PrintTicker`, `PrintAndSigns`, `ProductGallery`, `FeaturedSignage`, `HowItWorks`, `AboutPreview`, `Footer`).
- [`src/app/about/page.tsx`](file:///d:/client/jp-printing/src/app/about/page.tsx):
  - Tells the company story: Jot & Deepi Panag's direct client collaboration, local Ontario fabrication, and complete overview of capabilities.
- [`src/app/contact/page.tsx`](file:///d:/client/jp-printing/src/app/contact/page.tsx):
  - Full-featured customer intake page featuring dynamic quote request category toggles, direct phone/email contact cards, business hours, and an interactive FAQ accordion.
- [`src/app/services/page.tsx`](file:///d:/client/jp-printing/src/app/services/page.tsx):
  - Overview catalog displaying category counts (12 Printing, 12 Signs) with interactive filter tabs and live search.
- [`src/app/services/[slug]/page.tsx`](file:///d:/client/jp-printing/src/app/services/%5Bslug%5D/page.tsx):
  - **Dynamic Static Page**: Uses `generateStaticParams()` to pre-render 24 unique static landing pages for every print and signage service.
  - Generates bespoke SEO metadata (`title`, `description`) for each service.
  - Renders a technical specification matrix (stocks, finishes, sizes, weather-resistance), popular commercial use cases, feature checklist, direct quote CTA, and 3 related services in the same category.

### 3.6 Build & Runtime Artifacts (`out/`, `.open-next/`)

- **`out/`**: Contains the complete static HTML export output generated by `npm run build` (`next build`). Contains **31 pre-rendered static HTML routes** (`index.html`, `about/index.html`, `contact/index.html`, `services/index.html`, and 24 individual `/services/[slug]/index.html` pages) plus hashed CSS/JS chunks and font assets in `_next/static/`. This directory is deployed directly to **Cloudflare Pages**.
- **`.open-next/`**: Generated by `@opennextjs/cloudflare`. Contains:
  - `worker.js`: Cloudflare Workers runtime entrypoint that proxies requests, handles SSR/ISR, and serves static assets.
  - `assets/`: Static asset bundle mapped to the Cloudflare `ASSETS` binding.

## 6. Cloudflare Deployment & Infrastructure

The project is structured to deploy smoothly to either **Cloudflare Pages** (static export) or **Cloudflare Workers** (edge SSR/ISR with OpenNext):

### Option A: Cloudflare Pages (Recommended for Git CI/CD)
1. **Source Branches**: Keep both `main` and `master` synchronized:
   ```bash
   git push origin main
   git push origin main:master --force
   ```
2. **Cloudflare Dashboard Settings**:
   - **Framework Preset**: `Next.js (Static HTML Export)` *(or `None`)*
   - **Build Command**: `npx next build`
   - **Build Output Directory**: `out`
   - **Environment Variable**: `NODE_VERSION: 20` or `22`

### Option B: Cloudflare Workers with OpenNext & R2 Cache
Configured in `wrangler.jsonc` and `open-next.config.ts`:
1. **Create the R2 Cache Bucket**:
   ```bash
   npx wrangler r2 bucket create web-jp-printing-cache
   ```
2. **Deploy Bundle Directly**:
   ```bash
   npm run deploy
   ```
   *(Executes `opennextjs-cloudflare build && opennextjs-cloudflare deploy`)*

## 8. Maintenance Rules & Architectural Guardrails

1. **Preserve CSS Modules**:
   - **Never** add blanket wildcard loaders matching `*.css` in `next.config.ts`. Doing so strips CSS Module class hashing and breaks production layouts.
2. **Logo Constraints**:
   - Always maintain explicit `max-width`, `height`, and `object-fit: contain` on the logo element in `Navbar.module.css` across all breakpoint queries.
3. **Adding New Services**:
   - To add or modify a service, update `services` in [`src/data/services.ts`](file:///d:/client/jp-printing/src/data/services.ts). Because routes are statically generated via `generateStaticParams()`, Next.js will automatically create the route `/services/[new-slug]` at build time.
4. **Static Export Compatibility**:
   - Because `output: "export"` is active in `next.config.ts`, do not use Node.js runtime-only server actions or dynamic server-side cookies without a dedicated external API endpoint.
5. **Git Branch Synchronization**:
   - Keep `main` and `master` identical on the remote to prevent Cloudflare Pages CI from building stale commits.
